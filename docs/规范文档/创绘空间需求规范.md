## 一、总体架构

### 1.1 双模式系统

创绘空间包含两种工作模式，通过顶部中央 pill 形滑块切换：

| 模式 | ID | 定位 | 核心技术 |
|------|-----|------|---------|
| **手绘模式** | `#draw-hand` | 位图绘制 + 动态MR合成 | Canvas 2D + OffscreenCanvas + WebGL2 |
| **人偶模式** | `#draw-puppet` | Spine 2D骨骼动画预览与录制 | spine-webgl.js (用户自行提供) |

**切换控件：** pill 形滑块，白色背景滑块带微阴影，动画过渡 250ms

### 3.2 中央 — 画布区

#### 3.2.1 画布引擎

- 使用 `OffscreenCanvas` 在 Worker 中进行像素运算，主线程仅负责合成与显示
- 支持缩放 (pinch/scroll) + 平移 (space+drag)
- 默认画布尺寸跟随项目设置 (如 1920x1080)
- 背景支持纯色 / 透明棋盘格 / 导入底图
- 实时显示坐标标尺 (Rulers) 和参考线 (Guides)

#### 3.2.2 触控笔输入

**数据来源：** 捕获 Wacom/Huion 等数位板驱动通过 Pointer Events API 暴露的数据，**不依赖 Windows Ink API**。

捕获属性：

| 属性 | PointerEvent字段 | 说明 |
|------|-----------------|------|
| 压力 | `pressure` | 0.0 ~ 1.0，映射到笔刷大小/不透明度 |
| 倾斜X | `tiltX` | -90 ~ 90 度 |
| 倾斜Y | `tiltY` | -90 ~ 90 度 |
| 方位角 | `azimuthAngle` | 0 ~ 2π (rad) |
| 仰角 | `altitudeAngle` | 0 ~ π/2 (rad) |
| 笔ID | `pointerId` | 多笔触区分 |
| 按键 | `button` | 左键/右键/中键/橡皮擦(eraser) |

**事件处理要求：**
- 使用 `pointerdown` / `pointermove` / `pointerup` 事件
- `pointermove` 必须设置 `{ capture: true }` 确保跨窗口不丢帧
- 设置 `touch-action: none` CSS 阻止浏览器默认手势
- 压感曲线可配置 (线性 / 二次 / 自定义 LUT)
- 每个采样点插值密度不低于 60Hz

#### 3.2.3 画布交互

| 功能 | 说明 |
|------|------|
| 缩放 | 底部滑条 25%-400% + fit 按钮 |
| 平移 | 中键拖拽 / 空格+左键 |
| 绘制 | 左键绘制，根据选中工具 |

### 3.4 MR (Mixed Reality) 动态合成

#### 3.4.1 功能描述

手绘模式中，每个图层可设置为"MR动态图层"，该图层的内容将作为前景元素与时间线上的视频帧进行实时合成预览。

参考 **MOSO (Motion-Synchronized)** 融入现实项目的合成理念：前景元素需在光影、色彩、透视三个维度与背景场景匹配，实现"像真拍一样"的融合效果。

#### 3.4.2 合成流程

```
视频帧 (时间线当前帧, 背景)
    ↓
背景分析 (光影/色彩/透视提取)
    ↓
前景图层 (手绘/人偶/MR图层)
    ↓
┌─ 光影匹配 ──────────────────────────┐
│  环境光方向检测                       │
│  前景亮度/对比度自动适配              │
│  投影生成 (可选)                     │
└────────────────────────────────────┘
    ↓
┌─ 色彩匹配 ──────────────────────────┐
│  背景色彩统计 (色温/色调/饱和度)      │
│  前景色调映射 (3D LUT 生成)          │
│  高光/阴影分离着色                    │
└────────────────────────────────────┘
    ↓
┌─ 混合模式合成 (WebGL2 GPU加速) ─────┐
│  传统混合模式 (17种)                 │
│  + 光影混合模式 (新增5种)            │
│  + 色彩混合模式 (新增4种)            │
└────────────────────────────────────┘
    ↓
透视匹配 (镜头畸变/景深模拟)
    ↓
输出到监看画布
```

#### 3.4.3 MR图层特性

- 图层可关联时间线关键帧，在不同时间点显示不同内容
- 支持图层变换动画 (位移/旋转/缩放/倾斜)
- 图层可设置为"跟随时间线"或"固定帧"
- 合成使用 WebGL2 着色器实现，保证实时性

#### 3.4.4 光影匹配系统

##### 环境光方向检测

从背景视频帧中自动提取光源方向：

| 检测方法 | 说明 | 精度 |
|----------|------|------|
| 直方图分析 | 亮区/暗区分布推断光源方位 | 低 |
| 梯度分析 | Sobel算子提取边缘梯度，统计主要光照方向 | 中 |
| 深度学习 | 轻量CNN模型预测光照方向 (可选) | 高 |

```typescript
interface LightDirection {
  azimuth: number    // 水平方位角 0°~360°
  elevation: number  // 仰角 0°~90°
  intensity: number  // 光照强度 0~1
  colorTemp: number  // 光源色温 (K)
}
```

##### 前景亮度适配

```typescript
interface LightMatchParams {
  enableAutoMatch: boolean   // 自动匹配开关
  sourceBrightness: number   // 前景原始亮度
  targetBrightness: number   // 背景目标亮度
  contrastRatio: number      // 对比度比率 0.5~2.0
  shadowDensity: number      // 阴影密度 0~1
  highlightRoll: number      // 高光滚降 0~1
}
```

##### 投影生成

前景元素在背景上的投影：

| 投影类型 | 说明 | 参数 |
|----------|------|------|
| 硬投影 | 单光源清晰投影 | 角度/距离/模糊/颜色 |
| 软投影 | 多光源柔和投影 | 角度/距离/扩散/颜色 |
| 环境遮蔽 | 接触面AO阴影 | 半径/强度/采样数 |
| 接触阴影 | 物体接触面阴影 | 偏移/强度 |

#### 3.4.5 色彩匹配系统

##### 背景色彩分析

从背景帧实时提取色彩特征：

```typescript
interface ColorProfile {
  temperature: number    // 色温 (K), 2000~12000
  tint: number          // 色调偏移, -1~1
  saturation: number    // 平均饱和度, 0~1
  luminance: number     // 平均亮度, 0~1
  contrast: number      // 对比度, 0~1
  dominantHue: number   // 主色相, 0°~360°
  shadowColor: [number, number, number]  // 暗部色调 RGB
  highlightColor: [number, number, number] // 亮部色调 RGB
}
```

##### 3D LUT 自动生成

根据背景色彩分析结果，动态生成一个小型3D LUT用于前景色彩匹配：

```
1. 提取背景帧的色彩分布统计
2. 计算前景与背景的色彩映射关系
3. 生成 5×5×5 快速3D LUT
4. 在 GPU 上应用 LUT 到前景图层
```

##### 高光/阴影分离着色

```
前景图层
    ↓
亮度通道分离 (Luminance extraction)
    ↓
高光区 (L > 0.7) → 叠加背景高光色调
阴影区 (L < 0.3) → 叠加背景阴影色调
中间调 → 保持原色
    ↓
混合输出
```

#### 3.4.6 混合模式扩展

在传统17种混合模式基础上，新增光影和色彩专用混合模式：

**光影混合模式（新增5种）：**

| 模式 | 说明 | 算法 |
|------|------|------|
| 光线叠加 | 根据背景光照方向调整前景亮度 | `foreground * lightMap` |
| 阴影融合 | 仅在背景暗区显示前景 | `foreground * (1 - background)` |
| 高光透射 | 仅在背景亮区显示前景 | `foreground * background` |
| 环境遮蔽 | 前景接触面生成AO阴影 | `foreground * AO_map` |
| 体积光 | 模拟光线穿透前景效果 | `foreground + godRay(background)` |

**色彩混合模式（新增4种）：**

| 模式 | 说明 | 算法 |
|------|------|------|
| 色温融合 | 前景色温匹配背景色温 | `colorTemp( foreground, background.temp)` |
| 色调映射 | 前景色相偏移匹配背景主色 | `hueShift(foreground, bg.dominantHue)` |
| 饱和度匹配 | 前景饱和度适配背景 | `saturationMatch(foreground, bg.saturation)` |
| 色彩统一 | 强制前景使用背景调色板 | `paletteRemap(foreground, bg.palette)` |

#### 3.4.7 AI辅助合成 (可选)

当检测到本地可用的轻量推理引擎时，可启用AI辅助合成：

##### 支持的AI模型

| 模型 | 用途 | 推理方式 | 大小 |
|------|------|----------|------|
| MiDaS v2.1 | 单目深度估计 | ONNX Runtime (WebAssembly) | ~40MB |
| RMBG-1.4 | 语义分割/抠图 | ONNX Runtime (WebAssembly) | ~170MB |
| FastNERF | 光照估计 | ONNX Runtime (WebAssembly) | ~30MB |

##### AI合成流程

```
背景帧输入
    ↓
┌─ 深度估计 (MiDaS) ─────────────┐
│  输出: depth map (每像素深度值)  │
```

## 四、人偶模式

### 4.1 技术约束

> **关键约束：** spine-webgl.js 运行时文件 **不由本项目提供**。
> 用户必须自行准备 `spine-webgl.js` 文件并手动放入指定目录。
> 项目仅提供 TypeScript 类型定义 (`spine-webgl.d.ts`) 和胶水代码。

原因：Spine Runtime 使用 MIT + 商业双许可协议，自行分发存在侵权风险。

### 4.2 用户操作流程

```
1. 用户从 Esoteric Software 官网下载 Spine Runtime (spine-webgl.js)
2. 将 spine-webgl.js 放入项目目录: src/renderer/public/spine/
3. 启动应用，人偶模式检测 spine-webgl.js 是否存在
4. 若不存在 → 显示引导页面，提供下载链接和操作说明
5. 若存在 → 动态加载 spine-webgl.js，进入人偶模式
```

### 4.3 Spine 集成

#### 4.3.1 运行时加载

```typescript
async function loadSpineRuntime(): Promise<void> {
  const script = document.createElement('script')
  script.src = '/spine/spine-webgl.js'
  document.head.appendChild(script)
  await new Promise<void>((resolve, reject) => {
    script.onload = () => resolve()
    script.onerror = () => reject(new Error('spine-webgl.js not found'))
  })
}
```

#### 4.3.2 类型声明

项目中提供 `src/renderer/src/lib/spine/spine-webgl.d.ts` 类型声明文件，覆盖 spine-webgl.js 暴露的全局 `spine` 命名空间。
